# Definition of Done (DoD) - AgroValle Connect

Este documento constituye el **contrato técnico de calidad** aceptado por todos los integrantes del equipo. Ningún incremento funcional (Historia de Usuario) se considera terminado hasta que cumpla con la totalidad de los puntos listados a continuación.

## Checklist de Cumplimiento Obligatorio

- [x] **Build Local**: el proyecto compila o transpila sin errores en el entorno local (Java 17 / Spring Boot).
- [x] **Linter Pass (Modularity/Style)**: el código cumple con las reglas estáticas de Checkstyle, basado en Google Java Style (`checkstyle.xml`), con cero advertencias.
- [x] **Functional Correctness**: el 100% de las pruebas unitarias existentes pasan con éxito.
- [x] **Peer Review**: todo Pull Request ha sido revisado y aprobado por al menos un compañero de equipo tras una revisión de código.
- [x] **Documentation**: el `README.md` y la documentación técnica de la carpeta `/docs` están actualizados.
- [x] **Commits**: el historial del repositorio sigue estrictamente la convención de Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- [x] **Automatización**: los hooks de Husky (`.husky/pre-commit`) están activos e impiden el commit si falla el linter o las pruebas.



## Firma del Equipo

Al firmar (aceptar) este contrato, cada integrante se compromete a cumplir con el checklist anterior en cada entrega.
